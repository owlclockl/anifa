# Инструкции для агентов

## Проект

Это набор построек для Minecraft Java 26.3 в формате `.litematic`. Исходники генераторов и проверок лежат в `tools/` и `tests/`, инструкции — в `docs/`, основные описания — в `README.md`. Правки должны сохранять ванильную механику, заявленные размеры и количества, а также воспроизводимость схем из исходников.

## Визуальная работа: обязательный скилл unslop

В репозитории есть полная локальная копия скилла [unslop](https://github.com/heydamir/unslop) в `.agents/skills/unslop/` (автор Damir Sokolovsky, [@heydamir](https://x.com/heydamir), лицензия CC BY 4.0, версия зафиксирована на коммите `620163e`). См. `.agents/skills/unslop/SOURCE.md`.

**Когда читать и применять:** перед созданием или правкой любого визуального интерфейса — лендинг, дашборд, экран приложения, HTML/CSS, страница превью, обложка, анимация, а также по просьбам «unslop», «убери AI-вид», «сделай дизайн осмысленным». Для изменений только в логике, данных или схемах без визуального результата скилл не требуется.

Порядок работы берётся из `.agents/skills/unslop/SKILL.md` целиком, с нужными файлами из `references/`:

1. **Посмотреть результат глазами.** Найти файлы, которые отрисовывают экран; отрендерить или открыть в браузере и сделать скриншот. Скилл описывает отдельный сценарий, когда доступна только ссылка на живой сайт (скрипт `scripts/snapshot.mjs`).
2. **Аудит.** Пройти `references/signs.md` и перечислить каждый найденный признак «слапа» с указанием места. Для арабского, персидского, урду и иврита сначала прочитать `references/rtl.md` — его правила имеют приоритет.
3. **Оценить объём.** Полный прогон при множественных признаках; режим полировки, если экран в основном хороший; если «слапа» нет — прямо сказать об этом и предложить не больше двух-трёх точечных улучшений вместо переделки.
4. **Направление и пауза.** Записать пять строк: Product, Character, World, Moments, Signature; показать аудит и направление пользователю и дождаться ответа до правок. Паузу можно пропустить, только если пользователь уже разрешил действовать без согласования.
5. **Девять проходов по порядку:** spacing, color, icons, copy, type, layout, details, visuals, motion. Точные значения — в `references/tokens.md`, примеры — в `references/refs.md`, приёмы — в `references/effects.md`.
6. **Проверка и отчёт.** Пройти чек-лист из `SKILL.md`, отрендерить экран заново, сверить с перечнем аудита; в отчёте указать направление, ключевые изменения по проходам и промпты генерации изображений, если они были. Видео «история переделки» (story video) делать только по явной просьбе.

Ограничения этого репозитория при применении скилла: не переименовывать постройки, не менять факты, размеры, счётчики блоков и механику; не выдумывать данные и функции; насыщенный момент брать из самой постройки или честного рендера, а не из декоративного «глянца». При копировании или адаптации материалов скилла сохранять указание авторства и ссылку на исходный репозиторий.

## Проверки

После правок генераторов, схем или тестов запускать из корня репозитория:

```sh
python -m unittest discover -s tests -v
```
